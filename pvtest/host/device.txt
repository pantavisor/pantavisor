# Device Manifest
#
# Contains the configuration for identifying and communicating with a real
# device by pvtest framework.
#
# Install it in the host's pvtest config dir. Then, fill and uncomment:
#
#   mkdir -p ~/.config/pvtest/devices
#   cp device.txt ~/.config/pvtest/devices/<name>.txt
#
# See README.md to learn how to run.
#
#   name=   identifies this runner. Unique per board, e.g. dev-01, dev-02.
#   type=   class of target. Shared by every board of the same kind (e.g.
#           appengine). Used to filter test on "devices" from test.json.
#   ip=     device IP.
#   exec=   command prefix to run other commands on the device (e.g. ssh).
#   tty=    host serial device path. Prefer stable /dev/serial/by-id/... over
#           /dev/ttyUSBN.
#   baud=   optional. Default 115200.
#   setbootconfig= optional. Default will do best effort, any test whose
#           "config.env" is already not satisfied by the board is SKIPPED.
#           When set, it is invoked whenever a test initialization needs a
#           retype. That is, when test.json require a boot config that is
#           not set on the running device. Only used by --model persistent.
#   setbootconfig_conf= optional. Config file for the setbootconfig= command.
#   flash=  optional. Required by --model volatile, where it is invoked before
#           every test to flash the board with a fresh storage whose only
#           revision is the test.json initial one, booting with its boot config.
#   flash_conf= optional. Config file for the flash= command.
#
# setbootconfig contract
# Invocation:  <setbootconfig> [-c <setbootconfig_conf>] KEY=VALUE ...
# Inputs
#   argv    the complete set of boot-config tokens the board must boot with.
#   -c      setbootconfig_conf=, if set. Opaque to the tester.
#   env     the tester's own environment (under a lab wrapper that includes
#           whatever it exports, e.g. power-port commands).
#   console the tester releases tty= before the call and re-opens it after, so
#           the script may open the serial device exclusively.
# Outputs
#   exit 0  the args are the board's persistent boot config AND a reboot or
#           power-cycle has been started. Return as soon as it has. The
#           framework will already do the waiting until READY.
#   exit !0 failure.
#   stdout/stderr  captured to <workspace>/dev-setbootconfig-<name>-<id>.log.
# Must not: leave the serial device open on exit.
# Timing: the tester waits up to PVTEST_RETYPE_TIMEOUT (default 300 s) for the
# call to return. The tester also WARNs if the console shows no activity within
# 30 s of return.
#
# flash contract
# Invocation:  <flash> [-c <flash_conf>] -r <revision> -t <tarball-dir> KEY=VALUE ...
# Inputs
#   argv    the complete set of boot-config tokens the board must boot with.
#   -c      flash_conf=, if set. Opaque to the tester.
#   -r      factory revision name.
#   -t      host directory holding the container tarballs to be installed, to
#           be added in alphabetical order.
#   env, console as for setbootconfig.
# Outputs
#   exit 0  the board storage is fresh (no other revision, no Hub credentials,
#           logs or state left by a previous test). Its only revision is
#           <revision> (base plus the -t tarballs) committed as DONE. The arg
#           tokens are its persistent boot config. The boot has been started.
#           Return as soon as it has. The framework will already do the waiting
#           until device is READY.
#   exit !0 failure.
#   stdout/stderr  captured to <workspace>/dev-flash-<name>-<revision>.log
#           with / in <revision> replaced by _.
# Must not: leave the serial device open on exit.
# Timing: the tester waits up to PVTEST_RETYPE_TIMEOUT (default 3600 s) for the
# call to return.
